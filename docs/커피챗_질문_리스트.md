## 🎯 프로젝트 개요 및 소개

### 기본 정보
- **Stickr는 어떤 앱인가요?**
  > Stickr는 다양한 스티커를 탐색하고, 클립보드에 복사하여 인스타그램, 카카오톡 등 다양한 앱에서 바로 사용할 수 있는 React Native 기반 모바일 애플리케이션입니다. 사용자는 카테고리별로 분류된 스티커를 빠르게 검색하고, 원하는 스티커를 탭 한 번으로 클립보드에 복사할 수 있습니다.

- **프로젝트의 핵심 가치 제안은 무엇인가요?**
  > "스티커를 클립보드에 담아 어디든 붙여넣으세요" - 원클릭으로 스티커를 복사하고 인스타그램 등 다른 앱에서 바로 사용할 수 있는 간편함이 핵심입니다. 특히 인스타그램과의 원활한 연동을 위해 네이티브 모듈을 직접 구현하여 최적화된 사용자 경험을 제공합니다.

- **누구를 위한 앱인가요?**
  > 인스타그램 스토리, DM, 카카오톡 등에서 스티커를 활용하고 싶은 사용자들을 위한 앱입니다. 특히 소셜 미디어 콘텐츠 제작에 스티커를 자주 사용하는 사용자들에게 유용합니다.

- **개발 기간이 얼마나 걸렸나요?**
  > 2025-09-28부터 시작하여 현재까지 유지 보수 및 개선이 진행 중입니다.

- **1인 개발 프로젝트인가요?**
  > 네, 1인 개발 프로젝트입니다. 개발자 김민서가 프론트엔드부터 백엔드, 네이티브 모듈까지 전부 직접 개발했습니다.

- **앱의 주요 목적은 무엇인가요?**
  > 스티커 탐색, 복사, 공유를 한 곳에서 간편하게 처리할 수 있도록 하는 것이 주요 목적입니다. 특히 인스타그램과의 원활한 연동을 통해 사용자가 스티커를 복사한 후 바로 인스타그램에서 사용할 수 있도록 최적화되어 있습니다.

### 프로젝트 배경
- **왜 이 프로젝트를 시작하게 되었나요?**
  > 인스타그램 스토리나 DM에서 스티커를 사용할 때 기존 앱들은 복잡하거나 불편했습니다. 더 간편하고 빠르게 스티커를 복사해서 사용할 수 있는 앱을 만들고 싶었습니다.

- **스티커 앱을 만든 동기는 무엇인가요?**
  > 사용자가 스티커를 찾고 복사하는 과정을 최대한 간단하게 만들고, 특히 인스타그램과의 연동을 최적화하여 실제 사용 시나리오에 맞는 경험을 제공하고 싶었습니다.

- **기존 스티커 앱과의 차별점은 무엇인가요?**
  > 1) 원클릭 복사 기능 - 탭 한 번으로 클립보드에 복사, 2) 인스타그램 최적화 - 네이티브 모듈로 기존 인스타그램 태스크를 유지하며 전환, 3) 게스트 모드 지원 - 로그인 없이도 기본 기능 사용 가능, 4) React Query 기반 캐싱으로 빠른 검색 및 탐색

- **프로젝트 이름 'Stickr'의 의미는 무엇인가요?**
  > "Sticker"와 "Stick"의 조합으로, 스티커를 쉽게 붙여넣을 수 있다는 의미를 담고 있습니다. 간단하고 기억하기 쉬운 이름을 선택했습니다.

## ✨ 기능 관련 질문

### 스티커 탐색 및 정렬
- **어떤 카테고리로 스티커를 분류하나요?**
  > 전체, 손글씨(handwriting), 캐릭터(character), 말풍선(speech-bubble), 도트(dot), 이모지(emoji), 음식(food), 장식(decoration) 총 8개 카테고리로 분류합니다.

- **카테고리는 몇 개나 있나요?**
  > '전체'를 포함하여 총 8개의 카테고리가 있습니다. 각 카테고리는 한국어와 영어를 지원합니다.

- **인기순과 최신순 정렬은 어떻게 작동하나요?**
  > - **인기순**: `like_count DESC, auto_increment_id DESC` 순서로 정렬됩니다. 좋아요 수가 많은 순서대로 표시되며, 동일한 좋아요 수일 경우 최신순으로 정렬됩니다.
  > - **최신순**: `auto_increment_id DESC` 순서로 정렬됩니다. 가장 최근에 추가된 스티커부터 표시됩니다.

- **무한 스크롤은 어떻게 구현했나요?**
  > React Query의 `useInfiniteQuery`를 사용하여 구현했습니다. 커서 기반 페이지네이션을 사용하며, 각 페이지는 18개의 스티커를 로드합니다. `getNextPageParam`에서 `nextCursor`를 반환하여 다음 페이지를 자동으로 로드합니다.

- **스티커 목록은 어디서 가져오나요?**
  > Supabase 데이터베이스의 `sticker` 테이블에서 가져옵니다. `src/api/sticker.ts`의 `getRecentStickers`, `getPopularStickers`, `getMyFavorites` 함수를 통해 데이터를 조회합니다.

### 검색 기능
- **검색은 어떤 방식으로 작동하나요?**
  > 키워드 기반 실시간 검색입니다. 사용자가 검색어를 입력하고 검색 버튼을 누르면 `searchStickers` API가 호출됩니다. 검색어는 제목(title), 설명(description), 태그(tags)에서 검색됩니다.

- **검색은 제목과 태그 모두에서 이루어지나요?**
  > 네, 제목(title), 설명(description), 태그(tags) 세 가지 필드에서 검색됩니다. Supabase의 `ilike` 연산자를 사용하여 대소문자 구분 없이 부분 일치 검색을 수행합니다.

- **검색 결과는 어떻게 정렬되나요?**
  > 인기순으로 정렬됩니다. `like_count DESC, auto_increment_id DESC` 순서로 정렬되어 좋아요 수가 많은 스티커가 먼저 표시됩니다.

- **검색 성능 최적화는 어떻게 했나요?**
  > 1) React Query를 사용한 캐싱, 2) 검색 시 이전 캐시를 완전히 제거하여 중복 방지, 3) 커서 기반 페이지네이션으로 필요한 만큼만 로드, 4) 인덱싱을 통한 쿼리 성능 향상

- **검색 결과 캐싱은 어떻게 처리하나요?**
  > React Query의 `useSearchStickers` 훅을 사용하여 검색 결과를 캐싱합니다. 검색어가 변경되면 이전 캐시를 `queryClient.removeQueries`로 제거하고 새로운 검색 결과를 캐싱합니다.

### 스티커 복사 기능
- **스티커를 클립보드에 복사하는 방법은?**
  > 사용자가 스티커 카드를 탭하면 `handleCopyPress` 함수가 실행됩니다. 이미지를 먼저 다운로드한 후, 플랫폼에 따라 다른 방식으로 클립보드에 복사합니다.

- **Android와 iOS에서 복사 방식이 다른가요?**
  > 네, 다릅니다.
  > - **Android**: 네이티브 모듈 `ImageClipboardModule`을 사용하여 `FileProvider`로 생성한 `content://` URI를 클립보드에 등록합니다.
  > - **iOS**: `@react-native-clipboard/clipboard`의 `setImage`를 사용하며, 실패 시 base64 Data URL로 폴백합니다.

- **인스타그램에서 붙여넣기가 잘 작동하나요?**
  > 네, Android에서는 `FileProvider`를 통해 `content://` URI 형식으로 클립보드에 등록하여 인스타그램에서 정상적으로 붙여넣기가 가능합니다. iOS에서도 네이티브 클립보드 API를 사용하여 잘 작동합니다.

- **복사 실패 시 어떻게 처리하나요?**
  > 복사 실패 시 이미지 URL을 텍스트로 클립보드에 복사하는 폴백 처리를 합니다. 사용자에게 "URL 복사" 토스트 메시지를 표시합니다.

- **이미지 다운로드는 어디에 저장되나요?**
  > `react-native-fs`를 사용하여 캐시 디렉터리(`RNFS.CachesDirectoryPath`)에 임시로 저장됩니다. 파일명은 이미지 URL의 해시값을 사용합니다.

- **복사 후 임시 파일은 자동으로 삭제되나요?**
  > 네, 복사 완료 후 1.5초 뒤에 `setTimeout`을 사용하여 임시 파일을 자동으로 삭제합니다. `RNFS.unlink`를 사용하여 파일을 제거합니다.

### 인스타그램 연동
- **인스타그램으로 바로 이동하는 기능이 있나요?**
  > 네, 스티커 복사 성공 시 표시되는 토스트 메시지에 인스타그램 바로가기 버튼이 포함되어 있습니다. 이 버튼을 누르면 인스타그램 앱으로 이동합니다.

- **Android에서 기존 인스타그램 태스크를 유지하는 방법은?**
  > 네이티브 모듈 `AppSwitcherModule`을 구현하여 `FLAG_ACTIVITY_RESET_TASK_IF_NEEDED` 플래그를 사용합니다. 이를 통해 기존 인스타그램 태스크를 포그라운드로 전환하여 사용자가 작업하던 스토리가 초기화되지 않도록 합니다.

- **인스타그램 앱이 없으면 어떻게 되나요?**
  > 앱이 설치되어 있지 않으면 웹 브라우저로 폴백합니다. `Linking.canOpenURL`로 앱 설치 여부를 확인하고, 없으면 `https://www.instagram.com/`으로 이동합니다.

- **iOS에서 인스타그램 연동은 어떻게 하나요?**
  > 딥링크 `instagram://app`을 사용하여 인스타그램 앱을 실행합니다. 앱이 없으면 웹 URL로 폴백합니다.

### 즐겨찾기 기능
- **즐겨찾기는 어떻게 추가/제거하나요?**
  > 스티커 카드의 하트 버튼을 누르면 즐겨찾기가 추가/제거됩니다. `toggleFavorite` RPC 함수를 호출하여 서버에서 원자적으로 처리됩니다. Optimistic Update를 사용하여 즉각적인 UI 피드백을 제공합니다.

- **즐겨찾기는 로그인한 사용자만 사용할 수 있나요?**
  > 네, 즐겨찾기 기능은 로그인한 사용자만 사용할 수 있습니다. 즐겨찾기 화면에서 로그인하지 않은 사용자는 `LoginPrompt` 컴포넌트가 표시됩니다.

- **즐겨찾기 목록은 어떻게 정렬되나요?**
  > 즐겨찾기 추가 시간 기준으로 최신순으로 정렬됩니다. `created_at DESC, sticker_id DESC` 순서로 정렬됩니다.

- **즐겨찾기 상태는 어떻게 동기화되나요?**
  > React Query의 캐시를 Single Source of Truth로 사용합니다. 즐겨찾기 토글 시 `queryClient.invalidateQueries`를 사용하여 관련 쿼리를 무효화하고 자동으로 재조회합니다. Optimistic Update와 자동 롤백을 통해 안정성을 확보했습니다.

- **홈 화면과 즐겨찾기 화면의 상태가 자동으로 동기화되나요?**
  > 네, React Query의 캐시를 공유하기 때문에 홈 화면에서 즐겨찾기를 추가/제거하면 즐겨찾기 화면의 상태도 자동으로 업데이트됩니다. 반대로도 마찬가지입니다.

### 사용자 프로필
- **프로필 이미지는 어떻게 업로드하나요?**
  > 프로필 편집 화면에서 프로필 이미지를 선택하면 `react-native-image-picker`를 사용하여 이미지를 선택하고, AWS S3에 업로드합니다. 업로드된 이미지 URL을 Supabase의 `user_profiles` 테이블에 저장합니다.

- **닉네임 변경이 가능한가요?**
  > 네, 프로필 편집 화면에서 닉네임을 변경할 수 있습니다. 변경된 닉네임은 Supabase의 `user_profiles` 테이블에 저장됩니다.

- **프로필 정보는 어디에 저장되나요?**
  > Supabase의 `user_profiles` 테이블에 저장됩니다. 프로필 이미지는 AWS S3에 저장되고, 이미지 URL이 `user_profiles.avatar_url`에 저장됩니다.

- **게스트 모드가 무엇인가요?**
  > 로그인하지 않고도 앱의 기본 기능(스티커 탐색, 복사)을 사용할 수 있는 모드입니다. `AsyncStorage`에 `guestMode` 플래그를 저장하여 관리합니다.

- **게스트 모드에서도 모든 기능을 사용할 수 있나요?**
  > 아니요, 게스트 모드에서는 즐겨찾기 기능을 사용할 수 없습니다. 즐겨찾기는 로그인한 사용자만 사용 가능합니다.

## 🛠 기술 스택 및 아키텍처

### 프론트엔드
- **React Native 버전은 무엇인가요?**
  > React Native 0.81.4를 사용합니다.

- **TypeScript를 사용하는 이유는?**
  > 타입 안정성을 확보하고, 개발 시 오류를 미리 발견할 수 있으며, 코드 자동완성과 리팩토링이 용이하기 때문입니다.

- **상태 관리는 어떤 라이브러리를 사용하나요?**
  > Zustand와 React Query(TanStack Query)를 함께 사용합니다. Zustand는 전역 상태(테마, 언어 등)를 관리하고, React Query는 서버 상태(스티커 목록, 프로필 등)를 관리합니다.

- **Zustand와 React Query를 함께 사용하는 이유는?**
  > - **Zustand**: 클라이언트 전역 상태(테마, 언어 설정 등)를 간단하게 관리
  > - **React Query**: 서버 상태 캐싱, 동기화, 무한 스크롤 등 복잡한 서버 상태 관리에 최적화
  > 각각의 장점을 활용하여 적절한 도구를 적절한 곳에 사용하는 전략입니다.

- **네비게이션은 어떻게 구성되어 있나요?**
  > React Navigation을 사용합니다. `RootNavigation`에서 Stack Navigator를 사용하고, `BottomTabNavigation`에서 하단 탭 네비게이션을 구성합니다. 인증 상태에 따라 `AuthNavigation` 또는 `BottomTabNavigation`을 표시합니다.

- **컴포넌트 구조는 어떻게 설계했나요?**
  > 재사용 가능한 컴포넌트는 `src/components/`에, 화면 컴포넌트는 `src/screens/`에 분리했습니다. 커스텀 훅은 `src/hooks/`에, API 로직은 `src/api/`에 분리하여 관심사를 분리했습니다.

### 백엔드 및 데이터베이스
- **Supabase를 선택한 이유는?**
  > 1) PostgreSQL 기반의 강력한 데이터베이스, 2) 실시간 기능 지원, 3) 인증 시스템 내장, 4) RPC 함수 지원으로 복잡한 로직 처리 가능, 5) 무료 티어 제공, 6) 빠른 개발 속도

- **데이터베이스 스키마는 어떻게 설계했나요?**
  > 주요 테이블:
  > - `sticker`: 스티커 정보 (id, title, image_url, category, like_count 등)
  > - `user_profiles`: 사용자 프로필 (id, nickname, bio, avatar_url)
  > - `user_favorites`: 즐겨찾기 (user_id, sticker_id, created_at)
  > 관계형 데이터베이스 설계 원칙을 따르며, 외래키와 인덱스를 적절히 사용했습니다.

- **이미지 저장은 어디에 하나요? (AWS S3)**
  > 네, 이미지는 AWS S3에 저장됩니다. 프로필 이미지와 스티커 이미지 모두 S3에 저장되며, Supabase에는 이미지 URL만 저장합니다.

- **AWS S3와 Supabase를 함께 사용하는 이유는?**
  > Supabase는 데이터베이스와 인증에 최적화되어 있고, AWS S3는 대용량 파일 저장에 최적화되어 있습니다. 각각의 장점을 활용하여 이미지는 S3에, 메타데이터는 Supabase에 저장합니다.

- **API 엔드포인트는 어떻게 구성되어 있나요?**
  > Supabase 클라이언트를 직접 사용합니다. `src/api/` 디렉토리에 기능별로 분리되어 있습니다:
  > - `sticker.ts`: 스티커 관련 API
  > - `profile.ts`: 프로필 관련 API
  > - `supabaseClient.ts`: Supabase 클라이언트 설정

### 네이티브 모듈
- **Android 네이티브 모듈은 무엇을 하나요?**
  > 두 가지 네이티브 모듈이 있습니다:
  > 1) `ImageClipboardModule`: 이미지를 클립보드에 복사하는 모듈
  > 2) `AppSwitcherModule`: 다른 앱(인스타그램)으로 전환하는 모듈

- **ImageClipboardModule은 어떤 기능을 하나요?**
  > Kotlin으로 작성된 모듈로, `FileProvider`를 사용하여 로컬 파일 경로를 `content://` URI로 변환하고, `ClipboardManager`에 이미지 URI를 등록합니다. Android 10+ Scoped Storage 환경에서도 정상 작동합니다.

- **AppSwitcherModule은 무엇인가요?**
  > Android에서 기존 인스타그램 태스크를 포그라운드로 전환하는 모듈입니다. `FLAG_ACTIVITY_RESET_TASK_IF_NEEDED` 플래그를 사용하여 사용자가 작업하던 인스타그램 스토리가 초기화되지 않도록 합니다.

- **네이티브 모듈을 직접 구현한 이유는?**
  > 기존 라이브러리로는 인스타그램에서 이미지 붙여넣기가 제대로 작동하지 않았고, Android 10+ Scoped Storage 환경에서 `FileProvider`를 통한 URI 생성이 필요했기 때문입니다. 또한 인스타그램 앱 전환 최적화를 위해 직접 구현했습니다.

- **iOS 네이티브 모듈도 있나요?**
  > 현재는 없습니다. iOS는 `@react-native-clipboard/clipboard` 라이브러리로 충분히 작동하며, 인스타그램 연동도 딥링크로 처리 가능합니다.

### 아키텍처 패턴
- **프로젝트의 디렉토리 구조는 어떻게 되어 있나요?**
  > ```
  > src/
  > ├── api/          # API 통신 로직
  > ├── assets/       # 정적 리소스
  > ├── components/   # 재사용 컴포넌트
  > ├── config/      # 설정 파일
  > ├── constants/    # 상수 정의
  > ├── contexts/     # React Context
  > ├── hooks/        # 커스텀 훅
  > ├── navigations/  # 네비게이션 설정
  > ├── screens/      # 화면 컴포넌트
  > ├── store/        # 전역 상태 (Zustand)
  > ├── types/        # TypeScript 타입
  > └── utils/        # 유틸리티 함수
  > ```

- **API 레이어는 어떻게 분리했나요?**
  > `src/api/` 디렉토리에 기능별로 분리했습니다:
  > - `sticker.ts`: 스티커 관련 API 함수
  > - `profile.ts`: 프로필 관련 API 함수
  > - `supabaseClient.ts`: Supabase 클라이언트 인스턴스
  > - `queryClient.ts`: React Query 클라이언트 설정

- **커스텀 훅은 어떤 것들이 있나요?**
  > - `useAuth.ts`: 인증 관련 로직
  > - `useImagePicker.ts`: 이미지 선택 로직
  > - `useModal.ts`: 모달 상태 관리
  > - `useSupabaseSession.ts`: Supabase 세션 관리
  > - `useTranslation.ts`: 다국어 번역
  > - `hooks/keyboard/useKeyboard.ts`: 키보드 스마트 스크롤
  > - `hooks/query/`: React Query 훅들 (useInfiniteStickers, useSearchStickers 등)

- **Context API는 어디에 사용하나요?**
  > `FilterContext`에서 필터 상태(카테고리, 정렬 방식)를 관리합니다. 하위 컴포넌트에서 필터 상태를 공유하기 위해 사용합니다.

- **전역 상태와 로컬 상태는 어떻게 구분하나요?**
  > - **전역 상태 (Zustand)**: 테마, 언어 설정 등 앱 전체에서 공유되는 상태
  > - **서버 상태 (React Query)**: 스티커 목록, 프로필 등 서버에서 가져온 데이터
  > - **로컬 상태 (useState)**: 컴포넌트 내부에서만 사용되는 상태 (예: 모달 열림/닫힘)

## 🔧 개발 및 트러블슈팅

### 기술적 이슈 해결
- **키보드와 입력 필드 겹침 문제는 어떻게 해결했나요?**
  > `useKeyboard` 커스텀 훅을 구현하여 해결했습니다. `measureInWindow`로 입력 필드 위치를 측정하고, 키보드 높이를 계산하여 필요한 만큼만 화면을 이동시킵니다. `useState`의 비동기 특성으로 인한 계산 오류는 `useRef`로 해결했습니다. 자세한 내용은 `docs/키보드 겹침 문제.md`를 참고하세요.

- **인스타그램 앱 전환 최적화는 어떻게 했나요?**
  > Android 네이티브 모듈 `AppSwitcherModule`을 구현하여 `FLAG_ACTIVITY_RESET_TASK_IF_NEEDED` 플래그를 사용합니다. 이를 통해 기존 인스타그램 태스크를 포그라운드로 전환하여 사용자가 작업하던 스토리가 초기화되지 않도록 했습니다. 자세한 내용은 `docs/앱전환 안됨 문제.md`를 참고하세요.

- **즐겨찾기 상태 불일치 문제는 어떻게 해결했나요?**
  > React Query의 캐시를 Single Source of Truth로 사용하도록 변경했습니다. 모든 로컬 state를 제거하고, Optimistic Update와 자동 롤백을 통해 안정성을 확보했습니다. 자세한 내용은 `docs/즐겨찾기 상태 불일치 문제.md`를 참고하세요.

- **검색 결과 중복 키 이슈는 어떻게 해결했나요?**
  > Supabase 쿼리에 `ORDER BY` 절을 추가하여 해결했습니다. `like_count DESC, auto_increment_id DESC` 순서로 정렬하여 일관된 결과를 보장하고, 커서 조건과 정렬 순서를 일치시켰습니다. 자세한 내용은 `docs/검색 창 키 겹침 문제.md`를 참고하세요.

- **SVG 이미지 지원은 어떻게 구현했나요?**
  > `react-native-svg-transformer`를 사용하여 SVG 파일을 React 컴포넌트로 변환합니다. Metro 설정에서 SVG를 소스 파일로 인식하도록 설정하고, TypeScript 타입 선언을 추가하여 타입 안정성을 확보했습니다. 자세한 내용은 `docs/SVG직접사용 불가능 문제.md`를 참고하세요.

### 쿼리 및 최적화
- **페이지네이션은 어떻게 구현했나요?**
  > 커서 기반 페이지네이션을 사용합니다. 각 페이지는 18개의 스티커를 로드하며, 마지막 항목의 `like_count`와 `auto_increment_id`를 조합하여 `nextCursor`를 생성합니다.

- **커서 기반 페이지네이션의 장점은?**
  > - 오프셋 기반 페이지네이션보다 성능이 좋음 (데이터 추가/삭제 시 중복/누락 방지)
  > - 무한 스크롤에 최적화
  > - 일관된 정렬 보장

- **인덱싱은 어떻게 했나요?**
  > Supabase에서 자동으로 인덱스를 생성하지만, 자주 조회되는 컬럼(`category`, `like_count`, `auto_increment_id`)에 인덱스를 추가하여 쿼리 성능을 향상시켰습니다.

- **쿼리 성능 최적화는 어떻게 했나요?**
  > - 적절한 인덱스 추가
  > - 필요한 컬럼만 선택 (`select` 절 최적화)
  > - React Query 캐싱으로 불필요한 요청 감소
  > - 커서 기반 페이지네이션으로 필요한 만큼만 로드

- **RPC 함수는 어떤 것들이 있나요?**
  > - `toggle_favorite`: 즐겨찾기 추가/제거 및 `like_count` 동시 갱신 (원자적 처리)
  > - `delete_user`: 사용자 계정 삭제 (관련 데이터 모두 삭제)

## 🔐 인증 및 보안

### 인증 방식
- **소셜 로그인은 어떤 것들을 지원하나요?**
  > - Google (Android)
  > - Kakao (Android/iOS)
  > - Apple (iOS, 준비 중)
  > - 이메일/비밀번호 회원가입 및 로그인

- **Google 로그인은 어떻게 구현했나요?**
  > Android에서는 `@react-native-google-signin/google-signin`을 사용하여 네이티브 Google Sign-In을 구현했습니다. ID 토큰을 받아 Supabase의 `signInWithIdToken`으로 로그인합니다.

- **Kakao 로그인은 어떻게 구현했나요?**
  > Supabase의 OAuth를 사용하며, WebView를 통해 Kakao 로그인 페이지를 표시합니다. 콜백 URL에서 access_token과 refresh_token을 추출하여 Supabase 세션을 설정합니다.

- **이메일 로그인은 어떻게 작동하나요?**
  > Supabase Auth의 `signInWithPassword`를 사용합니다. 회원가입 시 이메일 인증을 요구하며, 인증 완료 후 로그인이 가능합니다.

- **Apple 로그인은 준비 중인가요?**
  > 네, iOS 배포 전에 Apple 로그인을 추가할 예정입니다.

## 🌐 다국어 및 테마

### 다국어 지원
- **지원하는 언어는 무엇인가요?**
  > 한국어와 영어를 지원합니다. `src/constants/translations.ts`에 모든 번역 텍스트가 정의되어 있습니다.

- **언어 전환은 어떻게 작동하나요?**
  > Zustand의 `useLanguageStore`를 사용하여 언어 상태를 관리합니다. 언어 변경 시 `AsyncStorage`에 저장하고, `useTranslation` 훅을 통해 번역된 텍스트를 가져옵니다.

- **번역 파일은 어떻게 관리하나요?**
  > `src/constants/translations.ts`에 `korean`과 `english` 객체로 번역 텍스트를 관리합니다. TypeScript의 타입 시스템을 활용하여 번역 키의 타입 안정성을 보장합니다.

- **시스템 언어 자동 감지는 어떻게 하나요?**
  > 앱 시작 시 시스템 언어를 감지하여 기본 언어를 설정합니다. `useLanguageStore`의 `loadLanguage` 함수에서 `AsyncStorage`에 저장된 언어를 우선 사용하고, 없으면 시스템 언어를 사용합니다.

- **동적 언어 변경이 가능한가요?**
  > 네, 설정 화면에서 언어를 변경할 수 있으며, 변경 즉시 앱 전체에 반영됩니다.

### 테마
- **라이트/다크 모드는 어떻게 구현했나요?**
  > Zustand의 `useThemeStore`를 사용하여 테마 상태를 관리합니다. `AsyncStorage`에 테마 설정을 저장하여 앱 재시작 후에도 유지됩니다.

- **테마 전환은 어떻게 작동하나요?**
  > 설정 화면에서 테마를 변경하면 `useThemeStore`의 `setTheme` 또는 `toggleTheme` 함수를 호출합니다. 변경된 테마는 즉시 앱 전체에 반영됩니다.

- **사용자 설정에 테마가 저장되나요?**
  > 네, `AsyncStorage`에 `themeMode` 키로 저장됩니다. 앱 재시작 시 저장된 테마를 자동으로 로드합니다.

- **다크 모드는 완전히 구현되었나요?**
  > 현재는 구현 중입니다. 기본 구조는 완성되었지만, 모든 화면과 컴포넌트에 다크 모드 스타일이 완전히 적용되지는 않았습니다.
