## 🎯 개요

### 낙관적 업데이트란?

**낙관적 업데이트(Optimistic Update)**는 서버 요청이 완료되기 전에 UI를 먼저 업데이트하는 패턴입니다. 사용자가 액션을 취하면 즉시 UI가 반응하여 빠른 피드백을 제공합니다.

### 현재 구현 위치

```typescript
// src/hooks/query/useToggleHeart.ts
export function useToggleHeart() {
  return useMutation({
    mutationFn: ({ stickerId }) => toggleFavorite(stickerId),
    onMutate: async ({ stickerId, currentIsFavorited, currentLikeCount }) => {
      // 낙관적 업데이트 로직
    },
    onError: (_err, _vars, ctx) => {
      // 에러 시 롤백
    },
    onSettled: () => {
      // 최종 정합성 보장
    },
  });
}
```

## ❓ 왜 낙관적 업데이트를 사용하나요?

### 문제 상황

**낙관적 업데이트 없이:**

```
사용자가 하트 버튼 클릭
    ↓
[로딩 스피너 표시] ⏳
    ↓
서버 요청 전송 (네트워크 지연)
    ↓
서버 응답 대기 (200-500ms)
    ↓
UI 업데이트
```

**문제점:**
- 느린 네트워크 환경에서 사용자 경험 저하
- 클릭 후 반응이 없어 답답함
- 매번 로딩 상태를 보여야 함

### 낙관적 업데이트 사용 시

```
사용자가 하트 버튼 클릭
    ↓
[즉시 UI 업데이트] ⚡ (0ms)
    ↓
서버 요청 전송 (백그라운드)
    ↓
서버 응답 대기
    ↓
성공: 그대로 유지 ✅
실패: 롤백 ❌
```

**장점:**
- 즉각적인 피드백으로 빠른 반응성
- 네트워크 지연을 사용자가 느끼지 않음
- 더 나은 사용자 경험

## 🔧 구현 상세

### 전체 코드 구조

```typescript
// src/hooks/query/useToggleHeart.ts
export function useToggleHeart() {
  return useMutation({
    // 1. 실제 서버 API 호출
    mutationFn: ({ stickerId }: Variables) => toggleFavorite(stickerId),

    // 2. 서버 요청 전 실행 (낙관적 업데이트)
    onMutate: async ({ stickerId, currentIsFavorited, currentLikeCount }) => {
      // 낙관적 업데이트 로직
    },

    // 3. 에러 발생 시 실행 (롤백)
    onError: (_err, _vars, ctx) => {
      // 롤백 로직
    },

    // 4. 성공/실패 관계없이 실행 (최종 동기화)
    onSettled: () => {
      // 캐시 무효화
    },
  });
}
```

### 1단계: onMutate - 낙관적 업데이트

#### 진행 중인 쿼리 취소

```typescript
// 경쟁 상태(race condition) 방지
await queryClient.cancelQueries({ queryKey: ['stickers'], exact: false });
await queryClient.cancelQueries({ queryKey: ['searchStickers'], exact: false });
```

**이유:**
- 낙관적 업데이트 중에 다른 쿼리가 실행되면 충돌 발생 가능
- 진행 중인 쿼리를 취소하여 일관성 유지

#### 현재 캐시 상태 백업

```typescript
// 롤백을 위한 백업
const prevStickers = queryClient.getQueriesData({ queryKey: ['stickers'] });
const prevSearchStickers = queryClient.getQueriesData({ queryKey: ['searchStickers'] });
```

**백업하는 이유:**
- 서버 요청 실패 시 이전 상태로 되돌리기 위해
- `onError`에서 사용할 수 있도록 context로 반환

#### 새로운 상태 계산

```typescript
// 즐겨찾기 상태 토글
const nextIsFavorited = !currentIsFavorited; // true ↔ false

// 좋아요 수 증감 계산
const likeDelta = nextIsFavorited ? 1 : -1; // 추가: +1, 제거: -1
```

**계산 로직:**
- `is_favorited`: 현재 상태의 반대값
- `like_count`: 즐겨찾기 추가 시 +1, 제거 시 -1

#### 캐시 업데이트 함수

```typescript
const updateStickerInPages = (old: any) => {
  // infinite query 구조가 아니면 그대로 반환
  if (!old || !Array.isArray(old.pages)) return old;

  // 모든 페이지를 순회하며 해당 스티커만 업데이트
  return {
    ...old,
    pages: old.pages.map((page: any) => ({
      ...page,
      data: page.data.map(
        (s: Sticker) =>
          s.id === stickerId
            ? {
                ...s,
                is_favorited: nextIsFavorited, // 즐겨찾기 상태 토글
                like_count: Math.max(
                  0, // 음수 방지
                  (s.like_count ?? currentLikeCount) + likeDelta, // 좋아요 수 증감
                ),
              }
            : s, // 다른 스티커는 그대로
      ),
    })),
  };
};
```

**핵심 포인트:**
- **Infinite Query 구조**: `pages` 배열을 순회하며 각 페이지의 데이터 업데이트
- **특정 스티커만 업데이트**: `s.id === stickerId` 조건으로 해당 스티커만 변경
- **불변성 유지**: 기존 객체를 변경하지 않고 새 객체 생성
- **음수 방지**: `Math.max(0, ...)`로 좋아요 수가 음수가 되지 않도록 보장

#### 모든 관련 쿼리 캐시 업데이트

```typescript
// 모든 stickers 관련 쿼리 즉시 업데이트
queryClient.setQueriesData(
  { queryKey: ['stickers'], exact: false },
  updateStickerInPages,
);

// 검색 결과 캐시도 즉시 업데이트
queryClient.setQueriesData(
  { queryKey: ['searchStickers'], exact: false },
  updateStickerInPages,
);
```

**업데이트되는 쿼리들:**
- `['stickers', 'popular', '전체']` - 홈 화면 인기순
- `['stickers', 'recent', '전체']` - 홈 화면 최신순
- `['stickers', 'popular', '이모지']` - 카테고리별
- `['stickers', undefined, 'favorites']` - 즐겨찾기 화면
- `['searchStickers', '검색어']` - 검색 결과

**`exact: false`의 의미:**
- 정확히 일치하는 쿼리뿐만 아니라 부분적으로 일치하는 모든 쿼리도 업데이트
- 예: `['stickers']`로 시작하는 모든 쿼리

#### 백업 상태 반환

```typescript
// onError에서 사용할 수 있도록 context로 반환
return { prevStickers, prevSearchStickers };
```

**반환값:**
- `onError` 콜백의 세 번째 인자(`ctx`)로 전달됨
- 에러 발생 시 롤백에 사용

## 📊 단계별 동작 과정

### 시나리오: 홈 화면에서 하트 클릭

```
[사용자 액션]
사용자가 스티커 카드의 하트 버튼 클릭
    ↓
[1. onMutate 실행] (즉시, 0ms)
    ├─ 진행 중인 쿼리 취소
    ├─ 현재 캐시 백업
    ├─ 새 상태 계산 (is_favorited: false → true)
    ├─ 모든 관련 캐시 즉시 업데이트
    │   ├─ 홈 화면 캐시 업데이트 ✅
    │   ├─ 즐겨찾기 화면 캐시 업데이트 ✅
    │   └─ 검색 결과 캐시 업데이트 ✅
    └─ 백업 상태 반환
    ↓
[UI 즉시 반영] ⚡
하트가 빨간색으로 변경됨 (사용자가 즉시 확인)
    ↓
[2. mutationFn 실행] (백그라운드)
    └─ toggleFavorite(stickerId) API 호출
    └─ 서버에 요청 전송
    ↓
[서버 처리]
    └─ RPC 함수 toggle_favorite 실행
    └─ 즐겨찾기 추가 + like_count 증가
    ↓
[3-1. 성공 시]
    └─ onSettled 실행
    └─ 캐시 무효화하여 서버 데이터로 동기화
    └─ 완료 ✅
    ↓
[3-2. 실패 시]
    └─ onError 실행
    └─ 백업된 상태로 롤백
    └─ onSettled 실행
    └─ 캐시 무효화하여 서버 데이터로 동기화
    └─ 에러 처리 ❌
```

### 실제 코드 실행 순서

```typescript
// 사용자가 하트 버튼 클릭
toggleHeart({
  stickerId: 'sticker-123',
  currentIsFavorited: false,
  currentLikeCount: 10,
});

// 1. onMutate 실행 (즉시)
onMutate: async ({ stickerId, currentIsFavorited, currentLikeCount }) => {
  // 진행 중인 쿼리 취소
  await queryClient.cancelQueries({ queryKey: ['stickers'], exact: false });
  
  // 캐시 백업
  const prevStickers = queryClient.getQueriesData({ queryKey: ['stickers'] });
  
  // 새 상태 계산
  const nextIsFavorited = !false; // true
  const likeDelta = 1; // +1
  
  // 캐시 즉시 업데이트
  queryClient.setQueriesData(
    { queryKey: ['stickers'], exact: false },
    (old) => {
      // 모든 페이지에서 sticker-123 찾아서 업데이트
      return {
        ...old,
        pages: old.pages.map(page => ({
          ...page,
          data: page.data.map(s =>
            s.id === 'sticker-123'
              ? { ...s, is_favorited: true, like_count: 11 }
              : s
          ),
        })),
      };
    },
  );
  
  return { prevStickers }; // 백업 반환
}

// 2. mutationFn 실행 (서버 요청)
mutationFn: async ({ stickerId }) => {
  return await toggleFavorite('sticker-123');
  // 서버에서 처리: 즐겨찾기 추가, like_count 증가
}

// 3-1. 성공 시
onSettled: () => {
  // 캐시 무효화하여 서버의 최신 데이터로 동기화
  queryClient.invalidateQueries({ queryKey: ['stickers'], exact: false });
}

// 3-2. 실패 시
onError: (_err, _vars, ctx) => {
  // 백업된 상태로 롤백
  ctx?.prevStickers?.forEach(([key, data]) => {
    queryClient.setQueryData(key, data);
  });
}
```

## ⚠️ 에러 처리 및 롤백

### onError 콜백

```typescript
onError: (_err, _vars, ctx) => {
  // 백업된 모든 쿼리 상태를 원래대로 복원
  ctx?.prevStickers?.forEach(([key, data]: any) =>
    queryClient.setQueryData(key, data),
  );
  ctx?.prevSearchStickers?.forEach(([key, data]: any) =>
    queryClient.setQueryData(key, data),
  );
},
```

**동작 방식:**
1. 서버 요청 실패 시 `onError` 실행
2. `ctx`에서 백업된 이전 상태 가져오기
3. 모든 관련 쿼리 캐시를 백업된 상태로 복원
4. UI가 낙관적 업데이트 이전 상태로 되돌아감

### 롤백 시나리오

```
[낙관적 업데이트]
하트가 빨간색으로 변경됨 (is_favorited: true)
    ↓
[서버 요청 실패]
네트워크 오류 또는 서버 에러
    ↓
[onError 실행]
백업된 상태로 롤백
    ↓
[UI 복원]
하트가 다시 회색으로 변경됨 (is_favorited: false)
    ↓
[사용자에게 알림]
에러 메시지 표시 (선택사항)
```

## ✅ 최종 정합성 보장

### onSettled 콜백

```typescript
onSettled: () => {
  // 모든 stickers 관련 쿼리를 무효화하여 서버에서 최신 데이터 가져오기
  queryClient.invalidateQueries({ queryKey: ['stickers'], exact: false });
  // 검색 결과도 무효화
  queryClient.invalidateQueries({ queryKey: ['searchStickers'], exact: false });
},
```

**왜 필요한가?**

낙관적 업데이트는 **예상된 상태**로 UI를 업데이트합니다. 하지만:
- 서버에서 추가적인 로직이 실행될 수 있음
- 다른 사용자의 액션으로 인해 상태가 변경될 수 있음
- 서버의 최종 상태가 예상과 다를 수 있음

**해결 방법:**
- 성공/실패 관계없이 `onSettled`에서 캐시를 무효화
- 서버에서 최신 데이터를 가져와서 정확한 상태로 동기화
- 낙관적 업데이트와 서버 상태의 차이를 자동으로 해결

### 동기화 플로우

```
[낙관적 업데이트]
예상 상태: is_favorited: true, like_count: 11
    ↓
[서버 처리 완료]
실제 상태: is_favorited: true, like_count: 11
    ↓
[onSettled 실행]
캐시 무효화
    ↓
[자동 재조회]
서버에서 최신 데이터 가져오기
    ↓
[최종 동기화]
UI가 서버의 정확한 상태로 업데이트됨
```

**장점:**
- 낙관적 업데이트로 빠른 반응성 제공
- 최종적으로 서버 상태와 정확히 일치 보장
- 사용자는 지연을 느끼지 않으면서도 정확한 데이터 확인

```typescript
// exact: false로 설정하여 모든 관련 쿼리 업데이트
queryClient.setQueriesData(
```

- 한 번의 업데이트로 모든 화면 동기화

- 일관성 보장

```typescript
// 불변성 유지로 메모리 효율적
return {
```

- 불필요한 메모리 할당 최소화

## 🔍 핵심 포인트 정리

### 1. 즉시 UI 업데이트
- 서버 요청 전에 캐시를 즉시 업데이트하여 빠른 반응성 제공

### 2. 모든 관련 쿼리 동기화
- `exact: false`로 설정하여 모든 관련 쿼리를 한 번에 업데이트
- 홈, 즐겨찾기, 검색 결과 화면이 자동으로 동기화

### 3. 안전한 롤백
- 에러 발생 시 백업된 상태로 자동 롤백
- 사용자에게 일관된 경험 제공

### 4. 최종 정합성 보장
- `onSettled`에서 캐시 무효화하여 서버 상태와 동기화
- 낙관적 업데이트와 실제 서버 상태의 차이 자동 해결

### 5. Single Source of Truth
- React Query 캐시를 유일한 데이터 소스로 사용
- 로컬 state 제거로 동기화 문제 근본 해결
